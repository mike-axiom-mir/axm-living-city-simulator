# Object Evolution Model — v0.3.0

## Root

Progression should not force the player to delete a visually preferred object merely because another catalogue item has better numbers.

## Identity

Each object retains a stable ID, type, owner/fixture mode, finish, condition, sentimental value, upgrade axes, footprint, position/storage location, creation/acquisition context, and history.

## Upgrade without replacement

Comfort, beauty, utility, durability, and efficiency can improve independently. Max-invested objects remain different because base traits, footprint, tags, maintenance, and function persist.

## Structural integration

An object now also exists in relation to a real room:

- footprint must remain inside one room;
- walls/doors cannot be crossed;
- power/water/waste needs must be present;
- household room permission must allow placement;
- construction may reflow or owner-store the object;
- structural completion proves the ID still exists.

## Fixtures versus personal objects

Property fixtures remain property-bound even when tenants move. Personal objects remain attached to their owner and move/store with that person. Relationship or property purchase does not relabel ownership.

## No-loss rule

Deletion is not a convenience for placement failure. A personal object that cannot fit goes to owner storage. A structural transaction that cannot preserve required fixtures or IDs fails and rolls back.

## Future depth

Materials can later split into frame, surface, component, craftsmanship, repair patch, provenance, and embodied history. The stable object ID must survive any richer representation.
